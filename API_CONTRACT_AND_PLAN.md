Error body for every 4xx: `{ "error": { "code", "message", "details"?: [{ "field", "message" }] } }`.
Every response carries `X-RateLimit-Limit` and `X-RateLimit-Remaining`; 429 adds `Retry-After`;
401 adds `WWW-Authenticate: Bearer`; 201 adds `Location`. Outside the 8 operations: unknown path ->
404, wrong method -> 405 with `Allow`, `OPTIONS` -> 204 (CORS).

How each status was produced (full log of 45 requests: `docs/api/ENDPOINTS.md`):

| Status | Produced by                                                                                                                                                                                                                                                         |
| :----- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 200    | Valid requests; `GET /products?page=99` returns 200 with empty `data` (not 404); `PUT` on an existing address id                                                                                                                                                    |
| 201    | `PUT /account/addresses/office` when `office` did not exist (with `Location`)                                                                                                                                                                                       |
| 400    | `limit=500`, `minPrice>maxPrice`, unknown `category`/`sort`, bad product id, login without fields, malformed JSON, `status=lost`, cancel reason over 200 chars, cancelling a delivered or already cancelled order (`ORDER_NOT_CANCELLABLE`), invalid address fields |
| 401    | `/account/*` without a token (`UNAUTHENTICATED`) or with an unknown token (`INVALID_TOKEN`); wrong password (`INVALID_CREDENTIALS`)                                                                                                                                 |
| 404    | Unknown product, unknown order `o-9999`, deleting an address twice                                                                                                                                                                                                  |
| 429    | 61st request within 60 s from one client on every operation (`RATE_LIMITED`); 6th failed login for one email within 60 s (`TOO_MANY_LOGIN_ATTEMPTS`)                                                                                                                |

## 4. Module Layout

| Folder            | Owns                                                                                                        | May import                 | Must not                                     |
| :---------------- | :---------------------------------------------------------------------------------------------------------- | :------------------------- | :------------------------------------------- |
| `src/utils/`      | Pure helpers: money in cents, cart math, query strings, validation, storage wrapper, DOM helper             | nothing from the app       | call `fetch`; read app state                 |
| `src/api/`        | Talking to the REST API: one fetch wrapper (`http.js`), one file per resource, `ApiError`                   | `utils/`                   | touch the DOM or state; store anything       |
| `src/state/`      | What the app remembers: cart, saved items, session, catalog filters; persistence through `utils/storage.js` | `utils/`                   | call the API (results are passed in)         |
| `src/components/` | Rendering and user events for one piece of UI; each exports `mount(root, deps)` and returns `unmount`       | `api/`, `state/`, `utils/` | import `main.js` or reach outside its `root` |
| `src/main.js`     | Composition root: creates the http client and stores, mounts components, connects 401 to sign-out           | everything                 | contain business logic                       |

Dependency direction: `main.js -> components -> (api, state) -> utils`. ESLint enforces it: restricted imports per folder, `fetch` only in `api/http.js`, Web Storage only in `utils/storage.js` (verified with probe files: 4 of 4 violations reported).

Full map, flows and the 31 files: `docs/ARCHITECTURE.md`. Every planned function exists as a
documented stub (JSDoc signature, throws "planned but not implemented"), so boundaries are reviewable
and lint-checked before coding begins.

## 5. Storage Strategy

| Data                                                                                                                                           | Where            | Key                     | Refresh   | Tab close                      | Logout      | Why                                                                                                                                                                                                 |
| :--------------------------------------------------------------------------------------------------------------------------------------------- | :--------------- | :---------------------- | :-------- | :----------------------------- | :---------- | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Cart lines (`productId`, `quantity`, price snapshot)                                                                                           | localStorage     | `brandstore:cart:v1`    | kept      | kept                           | kept        | A shopper expects the cart tomorrow and after signing out/in. It holds no personal data. Prices are re-checked against `GET /products/{id}` before checkout, so a stale snapshot cannot be charged. |
| Save-for-later items                                                                                                                           | localStorage     | `brandstore:saved:v1`   | kept      | kept                           | kept        | A wishlist is only useful if it lasts; same content and risk level as the cart.                                                                                                                     |
| Session: token, `expiresAt`, user `{id, name, email}`                                                                                          | sessionStorage   | `brandstore:session:v1` | kept      | **cleared**                    | **cleared** | Refresh must not sign the user out, but a bearer token should not outlive the tab (shared computers). Cleared on logout and on any 401.                                                             |
| Transient flags: `returnTo` after login, "session expired" notice, dismissed rate-limit banner, last cancelled order id for a one-time message | sessionStorage   | `brandstore:flags:v1`   | kept      | cleared                        | **cleared** | Only meaningful during this visit; must not leak into a later visit or another user's session.                                                                                                      |
| Catalog filters, sort, page                                                                                                                    | URL query string | n/a                     | kept      | n/a (in history and bookmarks) | unaffected  | Shareable and back/forward work; storing them would make the URL lie.                                                                                                                               |
| Products, orders, addresses from the API                                                                                                       | memory only      | n/a                     | refetched | gone                           | cleared     | The server is the source of truth. Orders and addresses are personal data and are never written to the device.                                                                                      |

Reasons and trade-offs (why not localStorage for the token, XSS, cart after logout, versioned keys,
private-mode failures): `docs/STORAGE.md`.
