# Handoff notes: API contract gaps for the backend team

**From:** BrandStore front end (Ahmed). **To:** TechSphere API team. **Date:** 2026-11-13.
**API:** TechSphere Store API 1.1 (`api/techsphere/openapi.yaml`, mock `server.py`).

Below is every place where the API's real responses differ from its spec, or where the spec leaves the
front end guessing. Each item gives what we observed, how the front end works around it today (the code
lives in `src/api/techsphere.js` unless another file is named), and what we are asking for. Items are
ordered by risk: the first ones can show a shopper a wrong price or let them order something unavailable.

|   # | Area                     | Observed                                                                                                                                                                                                                                     | Front-end workaround today                                                                                                                                                                                                                                                           | Request                                                                                                                                                                                          |
| --: | :----------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
|   1 | **Price type**           | `price` is a number in pounds (`32999`) for most products, but a formatted string for some (`"EGP 33,999"` on p-005 and p-014). Order `total` is a number in pounds.                                                                         | `priceToCents` strips everything but digits and the dot, then works in integer cents. An unreadable price becomes `NaN`, never 0.                                                                                                                                                    | One type: an integer in minor units (`3299900`) plus `currency`, on products and orders.                                                                                                         |
|   2 | **Stock**                | Only `stock_status` (`in_stock`, `low`, `out_of_stock`), and it is missing on some products (p-007, p-018). Assumed quantities are `in_stock` 25, `low` 3, `out_of_stock` 0, and the cart limits use them.                                                                                                                                                       | Make `stock_status` required and add `stock_quantity` (or `max_per_order`).                                                                                                                      |

Past the end, the catalog moves to the last page.                                                                                                                     | One scheme for every list (cursor or `page` plus `page_size`), with `page_size` in the response.                                                                                                 |

There is no alt text. | Root-relative paths are not loaded: they would cost 8 requests a page towards the rate limit and show nothing. Our placeholder is shown, with the product name as alt text. ## What the front end already guarantees

- The address comes only from `VITE_API_BASE`, falling back to `http://localhost:4010`. No other URL is fixed in the code (`src/config.js`).
- The token travels only in the `Authorization` header: never in a URL, a query string or a log (`docs/SECURITY.md` §6).
- Every request and response mapping above is covered by unit tests (`tests/unit/techsphere.test.js`, `tests/unit/edge-sweep.test.js`). End-to-end tests run against `server.py` on every pull request.

## Questions we need answered

1. Is `02/08/2026` 2 August or 8 February? (Item 5.)
2. Should a product without `stock_status` be sold? (Item 2.)
3. What should `POST /orders` do when a line is out of stock: reject the whole order, or place the rest? (Item 3.)
4. Will production send `Retry-After`, and how many requests per minute are allowed? (Item 9.)
